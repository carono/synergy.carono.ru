# LMS Synergy parser

Нативный парсер `https://lms.synergy.ru/` на Guzzle: логинится, проходит по дисциплинам текущего семестра, скачивает доступные видеоуроки и по SCORM-протоколу отправляет «просмотрено», чтобы разблокировать следующие уроки.

## Установка

```bash
cd lms-parser
composer install
cp .env.example .env
# отредактировать .env: LMS_LOGIN / LMS_PASSWORD
```

Плюс нужен Node с установленным Playwright — им проходится JS-челлендж DDoS-Guard
(см. «Сессия и DDoS-Guard»). Каталог установки указывается в `LMS_PLAYWRIGHT_DIR`.

## Запуск

```bash
./bin/parse                       # текущий семестр, скачать всё доступное и отметить просмотренным
./bin/parse --semester=4          # конкретный семестр
./bin/parse --discover-only       # только показать список семестров и дисциплин
./bin/parse --no-watch            # только скачивание, без эмуляции просмотра
./bin/parse --minutes=45          # сколько минут «просмотра» отправлять в SCORM
./bin/parse --no-retake           # не заглядывать во вкладку «Пересдача»
./bin/parse --retake=force        # всегда брать материалы из «Пересдачи», если вкладка есть
./bin/parse --discover-only --tabs --semester=4   # какие вкладки материалов есть у каждой дисциплины
./bin/parse --redo                # открыть уроки заново, не доверяя отметкам done в state.json
```

## Календарный график и сессия

```bash
./bin/session                     # текущий период + ближайшая сессия + расписание занятий за её даты
./bin/session --calendar          # только календарный график (/students/calend)
./bin/session --classes           # только расписание занятий за ближайшую сессию
./bin/session --dump              # сохранить HTML ответов в logs/ (для отладки парсера)
```

Источники:
- `/students/calend` — таблица «Семестр / Начало / Окончание / Мероприятие» по всем курсам (теор. обучение, экз. сессии, практики, каникулы).
- `/schedule/{academ,webinar,consultation,tutorplan,retake}` — конкретные занятия по вкладкам, фильтр POST'ом с `dateFrom`/`dateTo`/`mySchedule=1`.
- `/studentschedule` — список дисциплин текущего семестра с формой контроля (зачёт/экзамен) и плановыми часами.

## Что именно скачивается

Материал урока — это страница в iframe, и видео там не единственное содержимое.
`Parser::materials()` разбирает её и возвращает материалы трёх видов:

| Вид | Что это | Что делает парсер |
|---|---|---|
| `video` | `<video>` / `<source>` с mp4 (или m3u8) | качает |
| `file` | ссылка на файл: `pdf`, `doc(x)`, `ppt(x)`, `xls(x)`, `zip`, `rar`, `7z`, `ipynb`, `csv`, `txt`, `rtf`, `mp3`, `djvu` | качает |
| `link` | внешний ресурс вне LMS (например, ноутбук Google Colab) | дописывает в `materials.md` дисциплины |

Разбирается только `<body>` и без `<script>`: в разметке LMS попадаются строки
вида `var a = "/fake.pdf"`, которые иначе дают ложные срабатывания.

Соотношение на живом 4-м семестре: из 324 материалов видео — 143, остальные 181 —
конспекты (PDF в CDN или ссылка на Colab), практические задания и дополнительные
материалы (ZIP). Часть видеоуроков вдобавок несёт приложенный PDF со слайдами —
он сохраняется рядом с суффиксом (`z1.1_zanyatie_1.1.mp4` + `z1.1_zanyatie_1.1_1.pdf`).

`--redo` игнорирует отметки `done` в `state.json` и открывает уроки заново. Нужен
после расширения набора типов: прошлые прогоны успели отметить документы
сделанными, ничего не скачав. Повторный проход дешёвый — файлы, уже лежащие на
диске, `Downloader` не перекачивает.

## Задолженности и вкладка «Пересдача»

Если семестр закрыт с задолженностью, LMS помечает его иконкой-алертом (`icon-status-alert`
в строке семестра, подсказка «Задолженностей : N»), а проблемные дисциплины — иконкой
`icon-upd-failed` в столбце статуса. У таких дисциплин на странице материалов появляется
второй таб в блоке `#tabs-events`:

```
* Текущие     /student/updiscipline/{package}/{version}/1/1
  Пересдача   /lntools/versiongroupassign/contents/student/{disciplineId}/2
```

«Пересдача» — тот же курс, но открытый целиком: замки по тестам и датам сняты, а сами
тесты и итоговая аттестация из набора убраны. Разница на живом 4-м семестре:

| Дисциплина | Текущие | Пересдача |
|---|---|---|
| Цифровые платформы анализа данных | 103 урока, 91 заблокирован | 84 урока, 0 заблокировано |
| Базы данных | 81 / 75 заблокировано | 51 / 0 |
| Проектирование систем обработки больших данных | 60 / 53 | 38 / 0 |
| Программирование на языке Python | 43 / 37 | 25 / 0 |
| Методы машинного обучения | 174 / 163 | 126 / 0 |

`resourceId` уроков в обоих наборах одинаковые, поэтому `state.json` и структура папок
не меняются — пересдача просто добавляет доступ к тому, что раньше было под замком.

Режим работы задаётся `--retake`:

| Значение | Поведение |
|---|---|
| `auto` (по умолчанию) | открыть «Пересдачу», если по дисциплине есть задолженность или в «Текущих» есть заблокированные уроки |
| `force` | всегда предпочитать «Пересдачу», если вкладка есть |
| `off` (`--no-retake`) | игнорировать вкладку, работать только с «Текущими» |

При переходе на пересдачу снимается флаг `skipped` в `state.json`: прошлый отказ
«дисциплина требует прохождения теста» в этом наборе больше не актуален.

## Сессия и DDoS-Guard

`lms.synergy.ru` закрыт JS-челленджем DDoS-Guard — Guzzle и curl получают `403` со страницей
челленджа ещё до формы логина, headless-браузер тоже не проходит. Поэтому сессия поднимается
отдельной командой, видимым окном браузера:

```bash
./bin/cookies                     # пройти челлендж, залогиниться, записать cookies.json
./bin/cookies --headless          # без окна (обычно не проходит, оставлено для проб)
./bin/cookies --playwright=DIR    # где искать playwright, если не задан LMS_PLAYWRIGHT_DIR
```

Под капотом — `tools/ddg-bootstrap.mjs`: открывает сайт, ждёт, пока челлендж отработает,
логинится тем же XHR `POST /user/login`, что и форма на сайте, и печатает cookies в формате
`GuzzleHttp\Cookie\FileCookieJar`. Дальше `./bin/parse` и `./bin/session` работают из PHP,
пока сессия жива; когда она истечёт, они упадут с подсказкой «Обновите сессию браузером:
./bin/cookies».

В WSL окну нужен WSLg: `DISPLAY=:0 ./bin/cookies` от пользователя, у которого есть доступ к
дисплею.

## Логика

1. Логинимся через POST `/user/login` (форма `popupUsername` / `popupPassword`).
2. Скачиваем `/student/up` и через DomCrawler находим `<tbody class="semester sN expanded">` — это текущий семестр.
3. Для каждой дисциплины открываем `/lntools/versiongroupassign/contents/student/{id}` (LMS редиректит на `/student/updiscipline/...`).
4. На странице дисциплины читаем вкладки материалов (`#tabs-events`). Если есть «Пересдача» и режим `--retake` разрешает — перезагружаем страницу с её URL и дальше работаем с этим набором.
5. Собираем уроки из `li[data-index]`. Заблокированные уроки (`a.resourse_blocked`) пропускаем; если блокировка из-за теста — пропускаем дисциплину целиком (в наборе пересдачи этого правила нет).
6. Для каждого доступного урока:
   - открываем `/lntools/mcresource/view/{resourceId}/?...` (редирект на `/learning/view/{packageId}`),
   - читаем `php = {...}` инлайновый объект → `learningPackageId`, `firstItemId` из `tocItem`,
   - дёргаем `GET /learning/ajax/navigation_request/choice/0/{itemId}/{packageId}` → получаем `itemLink` (HTML с `<video>`),
   - вытаскиваем прямой MP4 URL (`<source src="...">`) и качаем (с поддержкой докачки через Range),
   - отправляем SCORM-cmi с `completionStatus=completed`, `totalTime=PT0H30M0S` через `save_data` + `navigation_request/exitall` + `close_lms`.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `LMS_LOGIN` / `LMS_PASSWORD` | учётка LMS |
| `LMS_OUTPUT_DIR` | куда складывать скачанное (по умолчанию `downloads/`) |
| `LMS_STATE_FILE` | путь к `state.json` (удобно подменять при отладке) |
| `LMS_USER_AGENT` | User-Agent для Guzzle |
| `LMS_REQUIRED_WATCH_MINUTES` | минуты «просмотра» по умолчанию |
| `LMS_PLAYWRIGHT_DIR` | каталог с установленным Playwright для `./bin/cookies` |
| `LMS_NODE_BIN` | путь к `node`, если он не в `PATH` |

## Замечания

- Время «просмотра» эмулируется на стороне сервера через те же AJAX, что делает плеер LMS. Если LMS поднимет валидацию (например, серверный таймер или watermarking) — нужно будет докрутить heartbeat-вызовы.
- `cookies.json` сохраняется между запусками — повторный запуск не делает лишний логин.
- `state.json` — idempotent: повторный прогон пропустит уже скачанные уроки.
- Вкладка «Пересдача» живёт ровно столько, сколько открыт период ликвидации задолженности,
  — после его окончания она исчезает, и `--retake=auto` просто ничего не найдёт.
